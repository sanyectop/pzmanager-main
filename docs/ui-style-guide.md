# PZManager 界面风格规范

> 适用范围：`src/App.tsx`、`src/App.css` 以及后续新增的 React/Chakra UI 页面。
>
> 本文总结当前项目已经采用的设计语言。规范与代码冲突时以代码为准，修改视觉样式后应同步更新本文。
>
> 核心方向：Windows 桌面工具、高信息密度、低视觉噪声、操作路径明确。不要把它做成宣传页或展示型大卡片界面。

## 1. 基本原则

1. **任务优先**：进入页面后首先看到可操作内容，不放营销 Hero、装饰性大标题或说明型首屏。
2. **信息密度优先**：列表、筛选器、状态和操作应尽量在首屏内完成扫描和操作。减少无意义留白，不牺牲可读性。
3. **视觉层级稳定**：标题、名称、ID、说明、标签、状态分别使用固定字号和颜色，不靠临时放大或加粗解决层级问题。
4. **一个页面一个主要滚动区**：桌面端尽量固定工具栏、筛选区和标题栏，只让列表正文滚动。
5. **卡片只承载独立对象或真正需要框定的工具**：禁止卡片套卡片，禁止把整页区块做成悬浮卡片。
6. **图标优先**：常见操作使用熟悉图标；文字按钮用于含义不直观或风险较高的命令。
7. **开发者模式只做渐进披露**：隐藏诊断信息、注入方法、冲突分析和详细通知；不能隐藏核心操作、错误信息或必要状态。
8. **状态必须完整**：每个异步区域都要有加载、空数据、错误和完成状态，不能只实现成功路径。
9. **动效克制且完整**：同时处理外层容器和内部内容，不能让正文在动、边框和高度却瞬间切换。
10. **颜色不能是唯一状态表达**：启用、禁用、危险、成功状态同时配合标签、图标、文本或边线。

## 2. 设计令牌

### 2.1 布局

| 项目 | 标准值 |
| --- | --- |
| 自绘标题栏高度 | `32px` |
| 顶部导航起始位置 | `1.5rem` |
| 顶部导航最小高度 | `3.5rem` |
| 页面内容间隔 | `0.8rem` |
| 主内容最大宽度 | `1400px` |
| 设置正文最大宽度 | `52rem` |
| 资源中心侧栏宽度 | `9.5rem` |
| 模组管理侧栏宽度 | `11.5rem` |
| 控件统一高度（输入框 / 原生下拉 / 下拉触发器） | `26px`，令牌 `--pz-control-height`，全应用一致 |
| 资源中心紧凑控件高度 | 同 `--pz-control-height`（原 `30px` 已并入该令牌） |
| 紧凑标签按钮高度 | 同 `--pz-control-height` |
| 普通面板内边距 | `1rem clamp(1rem, 2vw, 1.5rem)` |
| 模组折叠行基准高度 | `2.35rem` |
| 创意工坊列表项最小高度 | `4.75rem` |
| 冲突清单一屏行数 | `12` 行（行高 `1.375rem`、行距 `0.25rem`，清单限高 `308px`） |
| 图标按钮常规尺寸 | `1.6rem` |
| 模组图标尺寸 | `1.9rem` |
| 资源缩略图尺寸 | `42px` |
| 滚动渐隐带高度 | `1.75rem`，令牌 `--pz-scroll-fade-size` |

规则：

- 使用 `rem`、`px` 和 `clamp()`，不要按视口宽度缩放字体。
- 页面主结构使用 `flex` 和 `min-height: 0`，滚动区域显式设置 `overflow-y: auto`。
- 固定格式控件必须有稳定尺寸，悬浮、加载、切换文本不能改变工具栏或列表行高度。
- 允许滚动条槽位稳定时使用 `scrollbar-gutter: stable`。
- 滚动条统一用 `App.css` 顶部的 `*::-webkit-scrollbar*`（8px、胶囊滑块，箭头由 `::-webkit-scrollbar-button { display: none }` 关掉）。**不要加 `scrollbar-width` / `scrollbar-color`**：Chromium 见到这两个标准属性就会忽略 `::-webkit-scrollbar*`、改用原生主题滚动条，上下两端的箭头会跟着回来（`tests/scrollbarStyle.test.ts` 会拦）。
- 滚动容器在上下两端做渐隐：用 `mask` 作用在容器自身（子元素一起淡出），**不要盖一层渐变覆盖层**——玻璃/半透明背景的容器盖了就露出实心色块。渐隐带高度由 `scroll(self block)` 时间线驱动（`--pz-scroll-fade-top` / `--pz-scroll-fade-bottom` 注册为 `<length>`），贴住某一端时那一端为 0、不淡出；容器没有溢出时时间线不激活，两个值停在 `0px`。新增纵向滚动区要把它加进 `App.css` 里那份容器清单；带自身底色和描边的浮层（`.pz-workshop-tag-menu-content`）不要加，遮罩会把底色和圆角一起淡掉。

### 2.2 字体

| 用途 | 字号与字重 |
| --- | --- |
| 根字号 | `16px`，行高 `22px` |
| 页面主标题 | Chakra `lg`，通常为 `700` |
| 面板标题 | `sm` 或 `0.82rem`，`700` |
| 模组主名称 | `0.86rem` |
| 正文和说明 | `sm` 或 `xs` |
| 次级说明 | `xs`，颜色使用灰阶 |
| 微标签 | `0.68rem`，不应再小 |
| 顶部品牌标题 | `0.78rem`，`800`，字距 `0.08em` |
| 启动按钮主标题 | `1.3rem`，`800` |
| Toast 正文 | `0.85rem` |
| 数据、ID、路径、日志 | `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` |

规则：

- 主标题使用深色和高字重；ID、路径和版本号使用等宽字体并降低字号。
- 字距只在短标签、全大写或品牌标识上使用，范围约 `0.04em` 至 `0.12em`。
- 不使用负字距。
- 不用纯大字号代替信息层级；密集列表优先使用字重、颜色和间距区分。

### 2.3 颜色

| 角色 | 值 |
| --- | --- |
| 主操作蓝 | `#3182ce` |
| 主操作悬停蓝 | `#2b6cb0` |
| 选中文字蓝 | `#1a4f85` |
| 选中背景蓝 | `rgba(190, 227, 248, 0.70)` |
| 页面主文字 | `#1a202c` / `#2d3748` |
| 次级文字 | `#4a5568` |
| 弱化文字 | `#718096` / `#a0aec0` |
| 成功 | `#38a169` |
| 警告 | `#d69e2e` |
| 错误和危险 | `#e53e3e` |
| 启动页命令强调 | `#ff5c84` |
| 应用基础背景 | `#edf2f7` |
| 普通分隔线 | `rgba(113, 128, 150, 0.16)` 至 `0.24` |
| 玻璃面板背景 | `rgba(255, 255, 255, 0.38)` 至 `0.96` |
| 亚克力面板背景 | 浅色 `rgba(255, 255, 255, 0.6)`、深色 `rgba(32, 20, 28, 0.5)`（令牌 `--pz-surface-acrylic-light` / `--pz-surface-acrylic-dark`） |

规则：

- 蓝色只用于主操作、选中、焦点和进度，不把整页染成单一蓝色。
- 绿色只表示成功或正常完成；红色只表示错误、拒绝和危险操作；黄色只表示警告。
- 启动页允许使用深色玻璃和粉色强调，但只能作为启动页特殊场景，不能扩散成全局主题。
- **模糊强度可调**：全站每一处 `blur()`（`backdrop-filter` 与启动页克隆层的 `filter`）都必须写成
  `calc(<基准> * var(--pz-blur-scale, 1))`，不要写死像素；倍率由「设置 › 通用 › 模糊度」写到
  `documentElement` 上（0 = 关掉模糊，1 = 设计基准，2 = 上限）。新加毛玻璃时套这个写法，
  `tests/globalBlur.test.ts` 会拦住漏接的写死半径。
- **菜单亚克力**：所有下拉、多级子菜单、右键菜单和启动页的上弹面板共用一套——
  `backdrop-filter: blur(var(--pz-menu-blur)) saturate(var(--pz-menu-saturate))` + `--pz-menu-tint` 半透明底
  + `--pz-menu-noise-image` 极淡颗粒（直接当 `background-image`，不要用绝对定位伪元素：
  菜单内容会滚动，伪元素会跟着滚走）+ 顶边内高光 `inset 0 1px 0 var(--pz-menu-highlight)`。
  所有 `Menu.Content` 都挂 `.pz-workshop-tag-menu-content`（右键菜单用 `.pz-workshop-context-menu`），
  不要在单个菜单里另写底色。浮层会叠在任意内容上，所以**不能**套启动页那套"克隆壁纸"；
  但它们是短暂的、面积小的，用 `backdrop-filter` 没有整页面板那些问题。
  **前提是祖先链上没有 backdrop root**：任何带 `mask` / `filter` / `opacity < 1` / `clip-path` 的祖先都会
  让模糊只采到子树内容（等于没模糊）。启动页就是因为 `.pz-app-content` 的滚动渐隐 `mask-image` 中招，
  现已用 `.pz-app-content-launch { mask-image: none; }` 摘掉。改这两处时务必一起看。
- 亚克力（启动页的用户面板、启动面板）＝ 半透明底色（上面两个令牌）+ 一层极淡噪点（`::after` 画 `feTurbulence` 颗粒，`z-index: -1` 压在底色之上、正文之下，`opacity` 约 `0.14`）+ 玻璃描边与内高光。**启动页不再使用 `backdrop-filter`**（WebView2 下会出圆角光晕、壁纸切换拖影、四季壁纸掉帧，见 [acrylic-panel-options.md](./acrylic-panel-options.md)）；面板必须自带 `isolation: isolate` 兜住颗粒层的 `z-index: -1`。噪点必须 `pointer-events: none` 且 `border-radius: inherit`。「透过玻璃看」的效果由 `.pz-acrylic-glass` 提供（克隆壁纸层 + 面板形状裁剪，方案 C，见该文档第 5 节）：面板只要登记 `data-pz-acrylic`，不要再退回 `backdrop-filter`。
- 禁止紫色渐变主导界面，禁止大面积单一色系、装饰性光斑和无意义渐变。
- 字体对比度（设置 › 通用，`fontContrast` 0–100）用一条全局规则解决"文字和背景、特别是亚克力面板叠加后的底色太接近"：前端把 `--pz-text-contrast`（0–1）写在 `documentElement` 上，CSS 用 `color-mix(in srgb, <基准色> calc((1 - var(--pz-text-contrast)) * 100%), var(--pz-ink-strong))` 把浅色面上的文字往近黑推，0 = 完全保持上面的配色。要同时接管 Chakra 的灰阶（`--chakra-colors-gray-400`…`900`），因为大量文字是内联的 `color="gray.N"`；Chakra 的令牌在 `@layer tokens` 的 `:where(...)` 里，未分层的 `:root` 规则必定赢。深色面上的 `--pz-text-on-dark*` 不参与（往近黑推反而更看不清）。

### 2.4 圆角与阴影

| 元素 | 圆角 |
| --- | --- |
| 紧凑按钮、标签 | `0.35rem` 至 `0.4rem` |
| 普通按钮、列表行 | `0.45rem` |
| 弹层、菜单 | `0.4rem` 至 `0.55rem` |
| 主玻璃面板 | `0.7rem` |
| 胶囊、状态点、滑块轨道 | `999px` |

规则：

- 工具型界面不使用超大圆角。普通矩形控件圆角原则上不超过 `0.7rem`。
- 阴影用于表达层级和聚焦，不用于装饰。列表行优先使用边线和背景变化。
- 同一层级的面板只保留一层阴影，避免“卡片漂浮在卡片上”。

### 2.5 动效

| 场景 | 时长与缓动 |
| --- | --- |
| 按钮和表单反馈 | `160ms` 至 `180ms ease` |
| 页面淡入淡出 | `200ms ease` |
| 内容区入场 | `220ms cubic-bezier(0.22, 1, 0.36, 1)` |
| 弹层展开 | `240ms` 至 `320ms` |
| 列表详情展开 | `320ms` 至 `360ms` |
| 启动按钮左滑/停止按钮划入 | `300ms` 至 `320ms` |

规则：

- 展开/收起使用 `grid-template-rows: 0fr` 与 `1fr`，并同时动画外层 `background-color`、`border-color`、`box-shadow` 和内部 `opacity/transform`。
- 只让正文动、外层框瞬间出现或消失，视为未完成实现。
- 支持 `prefers-reduced-motion: reduce`，在该模式下关闭动画或压缩到近乎瞬时。
- 动效不能改变重要按钮的位置、列表行高和滚动位置。

## 3. 页面骨架

### 3.1 应用外壳

1. 窗口使用 Tauri 无边框模式，自绘标题栏固定在顶部。
2. 顶部导航悬浮居中，包含品牌、主导航和当前页面标签。
3. 启动页铺满正文区并使用背景图；其他页面在中部玻璃容器内显示。
4. Toast 固定在右上方，位于顶部导航下方，不能遮挡主要工具栏。

### 3.2 普通页面

普通内容页使用以下结构：

```text
.pz-main
  .pz-panel
    .pz-panel-header
    页面正文
```

- `.pz-panel` 本身保持透明、无边框、无阴影。
- 页面级玻璃边框由 `.pz-main` 提供。
- 页面标题和短说明放在头部，不要让工具栏承担标题职责。

### 3.3 资源中心和设置中心

以下页面必须沿用同一结构：

- 资源中心
- 设置
- Lua 模组管理
- JAR 模组管理

```text
.pz-resource-center
  .pz-resource-center-sidebar
    分类标题
    分类按钮
  .pz-resource-center-main
    当前分类正文
```

规则：

- 左侧只放分类导航，不放重复操作按钮。
- 当前分类使用蓝色浅底、深蓝文字和高字重，并设置 `aria-current="page"`。
- 正文区负责搜索、筛选、批量操作和滚动列表。
- 分类切换时正文执行统一的 `pz-content-enter` 动画。
- 设置页中的普通面板必须保留自身内边距，不能被资源中心专用的 `padding: 0` 规则误伤。

## 4. 组件规范

### 4.1 顶部和侧边导航

- 未激活的顶部导航显示图标和悬浮标签；激活项展开为图标加文字。
- 每个导航项必须有语义唯一、视觉可区分的图标。设置和模组管理不能复用同一个图标。
- 图标按钮必须同时提供 `aria-label` 和 `title`。
- 顶栏选择使用 `aria-current`，不要只依赖颜色。

### 4.2 按钮

- 主操作使用蓝色，危险操作使用红色，取消和次级操作使用 `outline` 或 `ghost`。
- 资源中心和设置中的普通按钮默认高度为 `30px`；标签按钮、以及与输入框/下拉同排的按钮跟随控件高度 `--pz-control-height`（`26px`），保证整行齐平。
- 一行内只保留一个最高优先级主按钮。
- 图标足以表达含义时使用图标按钮，例如关闭、刷新、搜索、设置、信息、下载、排序。
- 启动页的大尺寸“启动游戏”和“停止游戏进程”是全局唯一例外，两者必须完全共用尺寸、圆角、排版和悬停反馈。
- 所有按钮都应提供悬停、键盘焦点、按下、禁用和加载状态。

### 4.3 面板和分组

- 同一页面的标题、说明、操作区和正文按从上到下的顺序排列。
- 分组靠间距和分隔线，不靠层层边框。
- 设置默认不套额外卡片，只有独立下载任务、列表项或对话框才使用卡片。
- 概览页面允许多个平级信息块，但每个块必须提供有效信息，不能只放一个标题。

### 4.4 列表

#### 模组列表

- 折叠状态以 `2.35rem` 左右为基准，优先显示名称、内部 ID、作者或版本、关键标签和启停状态。
- 名称是主标题；内部 ID 使用更小、更弱的等宽字体；说明和路径按需截断。
- 启用状态使用开关或明确的左侧状态线，不要求用户先选中再点击“启用”。
- 排序、详情和更多操作放在悬停操作区或更多菜单中，避免常态占据横向空间。
- 选中、启用、禁用、拒绝四种状态必须视觉可区分。
- 滚出视口的行使用 `content-visibility: auto` 和稳定的 `contain-intrinsic-size`，并保留占位高度。

#### 资源与工坊列表

- 列表项保持一行式信息结构：缩略图、标题、说明、标签、元数据、操作。
- 元数据使用灰色小字，不能与标题争夺层级。
- 长名称和说明使用省略号或限制行数，不能让列表横向溢出。
- 缩略图不可用时使用统一占位符，不要保留巨大空白框。
- 悬停/聚焦高亮用 `--pz-radius-sm`（与按钮圆角一致）。高亮画在列表项的 `::before` 上（配合 `isolation: isolate` + `z-index: -1`），行的分隔线因此保持直角；不要直接给整行加 `border-radius`。
- 右键菜单挂在整行上（`Menu.Root` + `Menu.ContextTrigger asChild`，行本身仍是网格/弹性子元素），左键保持原有的直接动作；菜单项文案写清去向（「在 Steam 中打开」「在窗口内打开」），只有两项时不做分组和图标。
- 需要展示富文本详情时用模态弹窗，不要撑高行内区域：外壳复用光影下载弹窗的 `.pz-resource-file-overlay` / `.pz-resource-file-dialog`（含 `is-closing` 退场动画），并 `Portal` 到 `body`——`.pz-main` 带 `backdrop-filter` + `overflow: hidden`，会裁掉就地渲染的 `position: fixed` 弹层。详情正文用 `.pz-developer-news-content`，限高后自己滚动。
- 弹窗高度随内容变化（加载中 → 内容就绪）时不要瞬跳：用 `useDialogAutoHeight`（量出目标高度 → 从旧高度过渡 → `transitionend` 交还 `height: auto`，不把高度写死）。时长与缓动直接取自 `.pz-resource-file-dialog` 的 `height` 过渡，`prefers-reduced-motion` 下会被压到 `1ms`，所以过渡事件仍会触发、内联高度仍能交还。

#### 展开详情

- 展开按钮必须反映当前状态，并设置 `aria-expanded`。
- 展开前后的外部容器高度可以变化，但切换按钮的位置不能不可预测地跳动。
- 外层容器和内层正文同时动画。
- 展开后不能覆盖前一行的关键操作，也不能把滚动位置强行跳回顶部。
- 详情长度不可控时（例如冲突清单：25 个已批准模组实测 402 条，展开后曾高达 11754px），在详情内部限高、让清单自己滚动，一屏固定行数（冲突清单为 12 行）。行高与行距由清单作用域内的变量下发、限高用 `calc()` 算出，改行数或行高都不会算错；配合 `scrollbar-gutter: stable` 保证滚动条不挤压正文。

### 4.5 表单和筛选器

- 标签明确放在输入框外；占位符只用于示例，不能代替标签。
- 全应用的输入框、原生下拉与所有下拉触发器统一使用 `--pz-control-height`（`26px`）。该值取自资源中心「标签 › 包含/排除」两个下拉，保持一致才有意义，不要再逐处写死高度。资源中心筛选行、搜索行内的按钮同高，保证整行齐平。
- 搜索框应放在刷新和批量操作附近，300 个以上对象的列表必须支持搜索。
- 数值输入使用数字输入、滑块或步进器，并明确最小值和最大值。
- 筛选条件使用 `and` 关系时，状态筛选和标签筛选应可以组合。
- 选择型设置使用开关、菜单或分段控件，不用普通按钮模拟开关。
- 筛选类下拉的浮层宽度与触发按钮对齐：`WorkshopDropdown` 的浮层带 `.pz-dropdown-menu-content`，用 `min-width: var(--reference-width)`（zag 写在 positioner 上的按钮宽度）实现，选项文字更长时才允许超出，不截断。标签选择器、背景图菜单这类"内容一定比按钮宽"的浮层显式给 `minWidth`，不套这条。

### 4.6 Toast、错误和空状态

- Toast 位于右上角，宽度最大约 `360px`，默认展示约 3 秒。
- Toast 使用左侧状态色条和底部倒计时线，不显示大面积纯色背景。
- 普通模式只保留简短结果；开发者模式显示完整诊断信息。
- 错误始终显示可操作原因，不能因为非开发者模式而只显示“失败”。
- 空状态使用一行简短说明，不写教程式长文。
- 加载状态使用稳定高度的文本或骨架，不能用会改变页面布局的临时元素。

### 4.7 进度

- 下载进度条高度为 `6px`，扫描进度条为 `3px`，圆角为胶囊。
- 只有拿到真实分母时才显示百分比；未知进度只显示阶段文字。
- 进度不能伪造到 `100%`，也不能在完成前显示 `100%`。
- 覆盖层达到 `100%` 后应至少稳定显示 `2s`，再关闭覆盖层。
- 按钮加载状态要保留原宽度，不能因 spinner 出现导致工具栏抖动。

### 4.8 设置页

- 设置页使用与资源中心相同的左右结构。
- 通用设置最大宽度为 `52rem`，避免输入项横跨整个窗口。
- 每项设置由左侧标题与说明、右侧控件组成，窄屏时自动换行。
- 开发者模式只影响辅助信息和诊断细节。核心控件、错误和危险确认始终可见。
- 保存中的开关必须禁用，避免连续切换造成状态竞争。
- 跨页面共用的偏好放这里，不要在每个页面各放一份：翻译语言就是「通用 › 翻译语言」一项（`save_translation_language`），开发者新闻和创意工坊详情只显示进度、不再各自提供语言下拉。改语言后要作废按旧语言抓好的内容，下次进入时重取。
- 字体对比度同样是全局一项（`save_font_contrast`，0–100，默认 0）：滑块拖动时只改状态（CSS 变量立刻生效），落盘做 250ms 防抖；数值显示为百分比，左端标注「默认配色」。
- 「模组加载器」分类是加载器相关操作的唯一入口：方案选择（`save_mod_loader_scheme`）+ 该方案加载器的状态与安装。其它页面（支持库、模组管理）只报状态和指路，不复刻安装按钮或方案下拉；模组管理页在方案为「不使用」时要显示"未启用模组加载器"并给出跳转，而不是要求装 ZombieBuddy。
- 「启动」分类放启动阶段的实验性优化：「极速启动」（`save_fast_launch`），且**仅当模组加载器方案 = ZombieBuddy 时可用**——其它方案没有可短路的加载器，开关必须 `disabled` 并给出跳转提示。开关旁要写明三件事：缓存只收「已批准且启用」的模组；指纹与当前启用列表不一致、或注入任何一步异常，都会回退到 ZombieBuddy 原生扫描；该功能会向游戏进程注入代码，建议只在单机/自建服务器使用。
- 「启动」分类还有两项与加载器无关、任何方案下都可用：「静默内存清理」（`save_silent_memory_cleanup`：开关 + 30–95% 阈值滑块）与「启动时清理内存」（`save_clean_memory_on_launch`）。阈值滑块拖动时只改状态、落盘做 300ms 防抖；开关标题旁用 `Badge` 显示当前系统内存占用（后端 `get_memory_status`，超过阈值时换成橙色），滑块下方左「更频繁」右「更保守」标注方向；「立即清理一次」按钮报告上次释放量与耗时。
- 设置项里的选择控件和资源中心筛选行同款：复用 `WorkshopDropdown`（`.pz-workshop-menu-trigger` + `▾` + `.pz-workshop-tag-menu-content`），不要用原生 `<select>`——原生下拉的下拉箭头、内边距和字体跟全站对不上。

### 4.9 控制台和日志

- 加载控制台只显示最新 6 行，超出时从顶部淘汰。
- 日志、ID 和路径使用等宽字体，允许断词，不产生横向滚动。
- 非开发者模式隐藏 `[ZB]` 行数、耗时、DLL 路径等诊断字段。
- 控制台的阶段、行数和耗时保持同一行紧凑排列。

## 5. 启动页

- 启动页允许更强的视觉表现，但仍属于工具界面，不是营销落地页。
- 背景必须服务于当前创意工坊背景或用户背景，不能使用模糊、无关的装饰图。
- 「自定义背景」菜单顺序固定为：内置背景、自定义图片、创意工坊订阅。内置背景是随前端打包的图片（`public/backgrounds/`，不落用户磁盘），缩略图直接用打包 URL 的 `<img>`，不走 `read_background`；`backgroundPath` 为空时回落到内置背景当默认外观，所以不提供"纯色/无背景"这种会露出空画布的选项。
- 启动操作固定在右下区域；账号、创意工坊背景信息和命令参数不能互相遮挡。
- “启动游戏”点击后，主按钮和右上角设置、详情按钮左滑；停止按钮从右侧划入同一空间。
- 停止按钮必须与启动按钮同尺寸、同排版、同悬停反馈，并在父容器内居中。
- 启动时长文案单独占卡片底部一行，居中排在停止按钮副标题下面，字号 `--pz-font-sm`、弱化的深色面文字、数字用等宽字形；卡片高度按「标题 + 副标题 + 计时行」固定，文案出现或消失都不推动按钮。
- 游戏已经关闭时不能继续显示停止按钮。
- 创意工坊背景信息展开前后必须保持相同高度，箭头方向与状态一致。
- Steam 账号隐藏状态要持久化，隐藏后不保留可见文本残影，宽度变化不能推动相邻控件。

## 6. 响应式规则

### 6.1 中等宽度，`900px` 以下

- 隐藏次要徽章、模组描述和长元数据。
- 悬停操作改为常驻显示，兼容触控和窄屏。
- 搜索框和工具栏允许换行，但不能溢出父容器。

### 6.2 小窗口，`640px` 以下

- 资源中心和设置侧栏转为顶部分类条，允许横向滚动。
- 页面改为单一纵向滚动，关闭嵌套滚动区域。
- 启动页底部操作区改为全宽纵排，账号、命令和按钮不得重叠。
- Toast 宽度扩展为窗口宽度减去安全边距。

## 7. 无障碍和键盘

- 所有图标按钮必须有可读名称。
- 列表行作为选择控件时使用 `role="checkbox"` 和 `aria-checked`，不要嵌套原生 checkbox。
- 键盘焦点统一使用约 3px 的蓝色外圈。
- 菜单、弹层和对话框打开后要保证焦点可见，并支持 Escape 关闭。
- 颜色状态必须同时有文本、边线、图标或形状变化。
- 文本和背景对比度满足可读性要求，不使用浅灰文字承载关键信息。
- 尊重系统减少动态效果设置。

## 8. 代码约定

- 项目特定组合样式使用 `pz-` 前缀，例如 `pz-panel`、`pz-mod-row`、`pz-resource-center`。
- 单次布局、颜色语义可以使用 Chakra 属性；重复出现的视觉模式必须落到 `App.css`。
- 不新增 UI 框架。继续使用 Chakra UI、FontAwesome 和项目现有 SVG 图标。
- 不给根元素随意设置字体缩放，不使用负字距，不使用基于 `vw` 的字号。
- 新列表优先实现虚拟可视区域、内容休眠和稳定占位，避免 300 项以上同时重绘。
- 页面切换只改变当前内容区，不重建整个应用外壳。
- 不为解决局部问题引入全局 CSS 覆盖；优先提高选择器作用域。唯一例外是确有全局语义的统一规则（如控件高度 `--pz-control-height`），这类规则必须带注释说明基准来源。
- 修改交互后运行 `npm run build` 和相关 `node --test`。

## 10. 明确禁止

- 禁止宣传页式大标题、大幅装饰图和无操作价值的首屏。
- 禁止嵌套卡片和每段内容都包一层圆角阴影框。
- 禁止一个页面出现多个同等权重的大号主按钮。
- 禁止使用紫色渐变、装饰性光斑、模糊背景球作为默认设计语言。
- 禁止设置和模组管理等不同导航复用同一个图标。
- 禁止资源中心和设置页的正文边距失效。
- 禁止只给正文加展开动画。
- 禁止显示伪造的加载百分比。
- 禁止在加载进度到 `100%` 后立即撤除覆盖层。
- 禁止用颜色单独表达错误、选中或启用状态。
