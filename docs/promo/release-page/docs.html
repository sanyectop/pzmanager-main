文档中心

从安装到进阶用法,这里覆盖 PZManager 每个功能的说明与常见问题的排查方法。

快速上手

环境要求

  • Windows x64:游戏、启动器与覆盖层组件必须同为 64 位。
  • Steam 版 Project Zomboid:启动器依赖 Steam 环境探测游戏与创意工坊内容。
  • 建议分辨率 1280×720 及以上。

安装

  1. 从 下载页 获取最新版(GitHub Releases 或 123 云盘)。
  2. 解压到你喜欢的目录,运行 PZManager.exe。
  3. 首次启动时,程序会自动探测 Steam 与游戏路径:优先读取注册表,再回退到 Steam 的 libraryfolders.vdf 与 appmanifest 文件,多级回退确保各种安装方式都能找到。
提示:如果探测失败,请确认 Steam 已安装并且 Project Zomboid 已至少启动过一次(存在有效的库存清单文件)。

启动游戏

账户面板

启动页左下角显示 Steam 头像与 Persona 名。点击账户名可以隐藏/显示(用两条短横线遮挡),状态会被记住。

游戏内存

  • 范围从 1 GB 起,以 512 MB 步进,上限为系统物理内存。
  • 8 GB 处标有「推荐」,16 GB 处标有「参考线」;超过 16 GB 时会显示不稳定警告(游戏本身在大内存下可能出问题)。
  • 拖动滑块松手后自动保存,后端会再次校验,防止写入非法值。

启动参数

在启动详情弹层里逐条编辑 Java 启动参数,可增删。默认参数为 -agentlib:zbNative --(配合 ZombieBuddy 模组加载器使用,请勿随意删除)。

启动与停止

点击「启动游戏」后,按钮会进入 3 秒冷却并开始检测游戏进程;窗口就绪后按钮变为「停止游戏进程」。游戏自行退出时状态自动复位。

启动背景

启动设置弹层里可以选择内置背景、导入的自定义图片,或创意工坊模组自带的 title*.png 背景(四宫格拼接)。选中工坊背景时会显示来源模组信息。

启动时长

右下角显示「本次启动 xx.x s」,有历史记录时会显示与上次的差值,方便验证优化效果。

支持库与模组

支持库

「支持库」页面集中管理三项支持组件,每行是一张可折叠卡片,显示名称、一句话说明与状态标签:

组件作用说明
ZombieBuddy 模组加载器 JAR 模组的前置。安装入口在 设置 › 模组加载器,安装时会自动复制 DLL/JAR 并写入三处启动配置。
PZ Optimization 游戏优化 一键安装 / 更新 / 卸载,按 revision 比对判断是否可更新。
Viewpoint 3D 3D 模组配置 需要两个工坊模组全部订阅(Project Viewpoint、ZombieBuddy)后才能一键配置。

Lua 模组

「模组管理 › Lua」里可以调整加载顺序(依赖前置)、批量启用/禁用。顺序即生效优先级。

JAR 模组

「模组管理 › JAR」依赖 ZombieBuddy。启动器会扫描模组注解、分级提示冲突,由你逐个审批启用。

模组预设

把当前「Lua 加载顺序 + JAR 启停状态」保存为一个预设,之后一键切换整套模组组合,适合在不同整合包之间来回切换。

资源中心

创意工坊

「资源中心 › 创意工坊」直接浏览 Steam 创意工坊:支持排序、按时间/标签筛选、搜索与分页,结果有缓存加速。在列表里右键打开模组详情,介绍文本(BBCode)会按段自动翻译。大陆网络下,工坊请求会按「Steam 网络加速」的设置在直连与中转之间自动切换(见Steam 网络加速),无需手动配置。

光影下载

「资源中心 › 光影下载」检索光影资源:Modrinth 优先、CurseForge 兜底、必要时走镜像回退。下载任务进入全局任务中心后台进行,不阻塞界面。

开发者新闻

「资源中心 › 开发者新闻」拉取 Steam 官方新闻动态,翻译按 15 条一批进行,正文与标题都可以切换原文对照。

任务中心

标题栏右侧的「任务」按钮打开任务中心,所有后台下载的进度集中在这里查看。

Steam 网络加速

解决什么问题

启动器有三类请求需要访问 Steam:创意工坊列表(抓取 steamcommunity.com 的服务端渲染页并解析内嵌的 valve-ssr-data JSON)、项目详情(调用 Web API ISteamRemoteStorage/GetPublishedFileDetails)与开发者新闻(调用 ISteamNews/GetNewsForApp)。其中 steamcommunity.com 在大陆网络被墙——直连表现为 TCP 连接被重置或长时间无响应, api.steampowered.com 也时常不稳定。v1.2.261026 起,这三类请求统一接入 候选源 + 双向熔断机制,配合自建中转服务,大陆用户无需任何配置即可正常使用。

候选源与自动切换

每个请求按「候选源列表」顺序尝试,第一个成功的源返回结果,全部失败才报错(错误信息会 聚合每个源的具体原因)。候选源顺序由 设置 › 通用 › Steam 网络加速 的模式决定:

模式行为适用
自动(默认) 先直连官方,失败后自动改走中转;直连失败后进入 10 分钟熔断期,期间直接走中转不再空等直连超时。 大多数用户。海外网络直连秒回,大陆网络多等一次超时后自动切换。
中转优先 始终先走中转,中转故障时临时回退直连(同样有熔断保护)。 明确处于受限网络、不想每次先等直连失败的用户。
仅直连 完全不使用中转。 不希望请求经过任何第三方服务器的用户;大陆网络下工坊将不可用。

熔断是双向的:直连失败熔断直连(期间中转优先),中转失败同样熔断中转(期间直连顶上), 任一链路成功即解除熔断。这样单条链路的抖动不会把等待时间叠加到每次请求上。

中转服务的工作方式

中转是一个部署在自有服务器上的轻量反代(Node.js 单文件,源码见仓库 steam-relay/ 目录),采用路径白名单设计——只有下列前缀的请求会被代理, 其余一律 404,因此不能被当作任意代理使用:

路径转发目标服务端缓存
/community/*steamcommunity.com(工坊浏览 HTML)5 分钟
/api/*api.steampowered.com(详情 / 新闻 API,POST 表单透传)GET 5 分钟,POST 不缓存
/images/<host>/*Steam 图片 CDN,主机限白名单1 小时
/healthz无上游调用,返回 {"ok":true}无
  • 转发时统一覆盖为浏览器伪装头(UA、Accept-Language、Referer),降低被 Steam 风控的概率;上游 20 秒超时。
  • 图片白名单覆盖 Steam 各地区 CDN:steamusercontent、fastly / cloudflare / akamai 系 steamstatic 与 akamaihd(共 10 个主机)。
  • 缓存为进程内存缓存(TTL + 近似 LRU,上限 300 条):工坊 HTML 只有真正含 SSR 数据的响应才会入缓存——Steam 偶尔返回 HTTP 200 的风控 / 插页,缓存它们会让所有用户集体「无法解析」,这是专门防御的点。
  • 客户端本地也有 5 分钟的工坊 HTML 缓存,与服务端缓存叠加,第二次翻页通常明显更快。
「无法解析 Steam 页面」的防御:当某个源返回 200 但解析不出工坊数据(风控页 / 插页)时,启动器会把该源视为失败并立即换下一个源重试,而不是直接报错;配合服务端的 缓存守卫,坏页面最多影响一次请求。

预览图的兜底加载

工坊列表的预览图由 <img> 直接从 Steam CDN 加载(不走 Rust 网络层)。 图片加载失败时,启动器会按图片主机白名单把地址改写为中转的 /images/… 形式自动重试一次——即「原图优先、中转兜底」,原始地址可用时零额外开销。

本地代理(可选,进阶)

如果你在本机运行 Clash / V2Ray 等带本地端口的代理工具,可以在 设置 › 通用 › Steam 网络加速 填写「本地代理」,数据请求将直接经它发出, 通常比中转更快:

  • 支持 http://、https://、socks5:// 三种前缀; 只填 127.0.0.1:7897 这类裸地址会自动按 http 处理。
  • 「自动检测」会并行探测本机常见代理端口(7897 / 7890 / 1080 / 10808 / 10809 / 2080 / 7891), 对每个端口实际发起一次 Steam 请求,只有真正能访问 Steam 的才会列出,并自动填入延迟最低的一个。
  • 未填写本地代理时,启动器保持 reqwest 默认行为:自动读取 Windows 系统代理(WinINET)与 HTTP_PROXY 等环境变量——如果系统代理开着且可用,直连请求已经会走它。
  • 中转请求与「测试连接」始终绕过代理(直连中转服务器):这样即使系统代理残留了失效地址 (比如代理工具异常退出没恢复设置),中转兜底路径也不会被拖死。
关于 UU 等游戏加速器:这类加速器通过内核级 WFP 驱动按进程白名单加速 Steam 客户端(steam.exe / steamwebhelper.exe),不会接管启动器的流量——实测开着 UU 加速 Steam 时,启动器与 curl 直连 steamcommunity 仍会被重置。所以开着加速器≠工坊可用, 仍需保持本功能的自动 / 中转优先模式。

截图与光影

截图管理

集中展示 Viewpoint 3D 截图,支持列表浏览与预览,选中即可复制到剪贴板,方便直接粘贴分享。

光影管理

把光影 ZIP 包拖进窗口(或点击选择文件)即可导入,不会覆盖同名文件;支持删除、设置图标与搜索词。

游戏内覆盖层

启动游戏时,PZManager 会自动向游戏进程注入覆盖层组件(Hook OpenGL),在游戏加载阶段叠加显示进度界面,替代漫长的黑屏等待。

  • 覆盖层会话与启动流程绑定:游戏窗口就绪后开始工作,游戏退出或点击「停止游戏进程」后自动移除。
  • 注入原理、停止条件与排错表见仓库内的《覆盖层注入文档》(开发者文档)。
注意:覆盖层依赖 64 位环境。若游戏、启动器位数不一致,覆盖层不会生效,但不影响游戏本身启动。

设置详解

分类主要内容
通用 开发者模式(显示注入方法、模组标签、冲突分析与详细通知)、翻译语言、字体对比度、界面模糊度(亚克力/毛玻璃强度,0 为关闭)、Steam 网络加速(模式 / 中转地址 / 测试连接 / 本地代理 / 自动检测,详见Steam 网络加速)。
翻译器 开发者新闻与创意工坊说明的翻译行为设置。
控制台 启动时长记录查看、覆盖层会话调试。
下载器 下载并发、镜像偏好等下载行为设置。
模组加载器 ZombieBuddy 的安装与管理。
启动 内存清理(静默阈值 + 启动时清理一次)、极速启动(实验性)。
关于 版本信息、检查更新、反馈信息(详见问题反馈)。
关于「极速启动」:基于 JVMTI 的实验性功能,链路已打通,但游戏内仍有已知崩溃风险,追求稳定请勿开启。

问题反馈

遇到启动器或游戏内的问题时,可以使用 设置 › 关于 › 反馈信息 一键上报:上传最近一次启动的运行日志 + 你填写的问题描述, 提交成功后会显示一个反馈编号,无需手动找日志文件、压附件。

上传哪些内容

文件来源上传范围
%TEMP%\overlay.log 游戏内覆盖层组件的运行日志,由注入 DLL 跨启动追加写入 只截取最后一个「已加载」标记之后的部分,即最近一次游戏启动;不会把历史启动记录一起发出去
%USERPROFILE%\Zomboid\console.txt 游戏自身的控制台日志(每次启动由游戏重写,启动器追加 [PZManager] 标记) 整份文件,天然就是最近一次启动
  • 单个日志超过 4 MB 时只上传末尾部分(按字符边界安全截断),并在记录里标记 truncated,避免一次上传几十 MB。
  • 某个文件不存在(比如从没开启过覆盖层)时照常提交,记录里会标 missing。
  • 非 UTF-8 字节按替换字符解码,不会因编码问题提交失败。

隐私与时效

提交前请阅读弹窗内的提示:日志可能包含游戏安装路径、Steam ID 等本机信息,仅用于问题排查。按钮旁会标注当前时间——该按钮仅上传当前时刻前最后一次启动的日志, 请确保你描述的问题发生在那一次启动中;如果问题需要特定操作才能复现,先复现一次再回来提交。

服务端如何处理

  • 反馈以 JSON 形式落盘在中转服务器的 FEEDBACK_DIR 目录,文件名即反馈编号(时间戳 + 6 位随机后缀),提交成功后编号会显示给你,便于与开发者对照。
  • 单条请求上限 10 MB;描述最长 5000 字;同一 IP 每小时最多 10 条,超出返回「提交太频繁」。
  • 上传走中转服务器直连,不跟随系统代理——残留的失效代理不会让反馈发不出去。

常见问题

检测不到 Steam / 游戏?

确认 Steam 已正常登录安装,且 Project Zomboid 已安装并至少启动过一次。启动器通过注册表 → 库文件夹 VDF → 应用清单 ACF 三级回退探测,一般安装方式都能覆盖。

JAR 模组页面不可用?

JAR 模组管理依赖 ZombieBuddy 模组加载器,请先在 设置 › 模组加载器 完成安装。

Viewpoint 3D 一键配置按钮是灰的?

需要先在 Steam 创意工坊订阅全部两个模组:Project Viewpoint、ZombieBuddy,订阅后即可点击。

内存滑块拉到 16 GB 以上出现警告?

这是预期行为。Project Zomboid 在超大内存分配下自身可能不稳定,警告只是提醒,仍可继续保存。

游戏内没有出现覆盖层?

确认游戏与启动器都是 64 位;确认没有被杀毒软件拦截注入组件。更多排错步骤见覆盖层文档。

工坊 / 光影下载失败或很慢?

下载链路会自动尝试镜像回退,请检查任务中心里的具体报错;网络环境受限时建议稍后重试或切换网络。

极速启动后游戏崩溃?

极速启动目前是实验性功能,存在已知崩溃风险,请在 设置 › 启动 关闭后重试。

创意工坊列表打不开 / 提示「无法解析 Steam 页面」?

先到 设置 › 通用 › Steam 网络加速 确认模式不是「仅直连」(大陆网络下仅直连必然失败), 用「测试连接」确认中转可达;如果指向了自定义中转地址,检查地址是否写对(不要带末尾斜杠也能用,但域名要正确)。 偶发的「无法解析」通常是 Steam 返回了风控页,启动器会自动换源重试,再试一次即可;持续失败请通过 反馈 上报日志。

开了 UU / 加速器,创意工坊还是打不开?

正常现象:这类加速器通过 WFP 驱动按进程白名单只加速 Steam 客户端,不会接管启动器的网络请求。 启动器依赖自身的「Steam 网络加速」机制,保持「自动」或「中转优先」模式即可;如果你有 Clash / V2Ray 等本地代理,填入「本地代理」通常更快,详见Steam 网络加速。

本地代理「自动检测」没有发现可用代理?

检测只扫描常见端口(7897 / 7890 / 1080 / 10808 / 10809 / 2080 / 7891),且要求该端口能实际访问 Steam。 如果你的代理用了其它端口,请到代理工具的设置里确认「混合端口 / HTTP 端口」后手动填入; 只填 127.0.0.1:端口 即可,无需写协议前缀。

反馈提交失败,或反馈编号有什么用?

提交失败时弹窗会显示具体原因:日志缺失(两个日志文件都不存在)、提交太频繁(同一网络每小时 10 条上限) 或网络问题。编号是反馈在服务器上的唯一文件名,向开发者反馈问题时附上编号即可精准定位到你的日志; 提交成功后弹窗也会列出实际上传与缺失的文件。详见问题反馈。
